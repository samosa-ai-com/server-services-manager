If you run this manager on more than one machine, this page links them so you can monitor them from here.

  1. Set the same shared secret on every machine (cluster.secret in config.yaml) and restart each manager. Without it, peers reject each other's API calls.
  2. Add Peer below with the other machine's address + that same secret. Leave the secret blank to reuse this machine's own cluster.secret.
  3. Probe to check reachability (the dot on each card). Green means its /health answered.
  4. Open jumps to the peer's dashboard in a new tab (log in there with that machine's password). API calls made through the proxy use the shared secret automatically.

Nothing is broadcast automatically. With no peers added, this page simply stays empty — one machine is the normal case.

About

Cluster mode is off by default. To enable it, add a cluster: block to config.yaml: 

cluster:
  enabled: true
  secret: my-shared-secret     # must match on every peer
  port: 8881
  advertise: 192.168.1.100    # optional, override auto-detect

Cross-node API calls carry the shared secret in the X-SSM-Cluster-Secret header. LAN-only by design — for production deploy a TLS-terminating reverse proxy in front of every node. The proxy endpoint /api/cluster/node/<id>/proxy/<rest> forwards the user's session cookie so they appear logged in on the remote side.
